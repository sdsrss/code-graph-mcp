## 语言事实与做法（重做后）

`C.m` 是对类对象 `C` 的属性查找：沿 C 的 MRO（C3 线性化）找第一个定义了 `m` 的类；显式类调用不分派到子类覆盖。

- 解析器（`member.rs`）在一个文件内判定答案：`C` 及 MRO 上直到定义 `m` 的那个类，都必须是本文件的类，并且满足以下条件：
  - 在模块顶层恰好定义一次，不在 `if`/`try`/`with` 下，没有装饰器（装饰器可能返回别的对象）；
  - 没有关键字基类（`metaclass=`），定义之后没有 `from … import *`；
  - 文件里该名字的其他出现都是允许清单里的读取；
  - 这些类都不以别的方式绑定 `m`（类属性、第二个 `def`、条件 `def`），文件也不从外部给它赋值或删除（`C.m = f`、`del C.m`）。

  满足时，调用带 `{"own":1,"q":"super","v":"<定义 m 的类>"}`。C 自己定义了 `m` 时，不管基类是什么都算判定成功。MRO 上碰到本文件判定不了的类（导入的、内建的、`object`、被重新绑定的名字）就放弃，保持旧解析。
- 解析器没有判定的调用，以及 `super()` 调用，都与 0.182.0 完全相同。
- 解析结果：`recv_type_targets(v, dispatch=false)` 取名为 v 的类自己的方法。几个同名类都定义了它时，取调用方文件的那个。因为解析器确认过本文件的 v 用一个 `def` 定义了 `m`，这个答案与其他文件无关。
- `"own":1` 让类结构漂移扫描（`typed_callers_of_class_drift`）跳过这些调用：答案不随其他文件变化，扫描只会增加增量成本。

## 接受与拒绝的形态

读取（接受）的位置：
- 类定义本身；属性对象 `C.x`、`C.x = 1`；被调用 `C()`；参数与基类 `f(C)`、`class D(C)`；赋值右边 `E = C`。
- 注解 `x: C`、`def f(a: C) -> C`；运算数、`return`、装饰器、f-string、字典键值。
- `assert`/`raise`/`if`/`while` 条件；`except C:`、`except C as e`、`with C as x`（C 是读取，e、x 是绑定）；`case C():`。
- 元组、列表、集合、字典、括号、`*`/`**` 先向上越过，再按外层语句判定。

拒绝的形态，保持旧解析：
- 任何赋值目标（含元组、列表、星号、带注解、增量赋值）；各种形参；`for`/推导式目标；`with … as C`（含 `as (a, *C)`）、`except E as C`；`case D() as C`、`case C:`。
- 任何 import 绑定；`global`/`nonlocal`；`del`（含 `del a, C`）；海象赋值。
- 同名 `def`（含方法），同名的嵌套类、类内类、类属性；同名类定义两次；条件定义或带装饰器的类；`metaclass=`；类型参数、`type C = …`；类定义之后的 `from x import *`。
- 接收者不是 C 本身（`self.C.m()`、`C.D.m()`、`C().m()`、`x.C.m()`）。
- 允许清单之外的位置一律拒绝。

MRO 判定的形态见 `test_python_call_on_a_module_level_class_binds_the_mro_owner`：
- 绑定：自己的方法；单继承；深度优先先于广度（`C(A, B)`、`A(Base1)` → Base1）；菱形；基类不是本文件的类但 C 自己有 `m`；内建基类排在定义类之后。
- 放弃（第 2 轮后新增）：基类定义在下方；C 或它派生自的本文件类带 metaclass；C 自己有 `m` 但 MRO 不一致；`def` 的装饰器、默认值、注解或嵌套类的基类里有绑定 `m` 的海象；`(C).m = f`、`del (C).m`；类名或方法名是 `__x`；MRO 超过 64 个类。链长 41 现在能判定（原来超过 32 就放弃）。
- 放弃：基类不是本文件的类且 C 自己没有 `m`；`mod.Base` 写法的基类；定义类前面有导入的基类或内建基类；整个文件都没有定义 `m`；类属性同名；条件 `def`；两个 `def`；基类带 metaclass；基类的方法被外部赋值；MRO 不一致；基类名被重新绑定；类名是 `std`。

已知仍错、本项不处理：`m` 来自外部基类或内建基类时，旧解析仍按名字绑本文件的同名方法。

- 只认模块级、无条件、无装饰器的类：函数内的类（flask 测试里的 `Index.as_view`）和带装饰器的类（`@dataclass`）保持旧规则。

## 遗留

- 标准库默认层剩 2,832 条错边。按 BASE 的计数，最大几类：
  - 未定型 `x.m()` 绑到本文件同名方法：去掉本项那 2,057 条后约 740 错。
  - `from x import C` 或模块限定的 `m.f()` / `m.x.f()` 绑进调用方自己的文件：453 错 / 33 对，33 条多为 oracle 的覆盖记分。
  - 跨文件未定型成员调用：406 错 / 48 对。
- 方法名同时是内建类型方法名（`get`/`append`/`close`…）时，同文件未定型成员调用在标准库是 272 对 / 2,564 错，在 flask 是 2 对 / 2 错。这可以作重新标注的依据，但要先按语言模拟。
- oracle 对显式类调用 `Base.m(self)` 也给子类覆盖记正确，会把本项这类修复算成“丢正确”。`scripts/scip_oracle/oracle.py` 的覆盖记分可以排除这种调用形态。
- `super()` 的第一基类在别的文件有同名类时，仍按名字绑（asyncio 的 `_FlowControlMixin.__init__` 绑到 xmlrpc 的 `Transport.__init__`）。第一版修了这条，但代价是 r01/r02；要修，需要同样“在文件内判定”的前提。
- metaclass 的精确规则（第 2 轮 F5 的代价，80 条错边、都在 `_pyio.py`）：只有本文件定义的 metaclass 绑定了同名名字或 `__getattribute__` 时才放弃，导入的 metaclass 按假设放行，与导入基类一致。它改掉“带 metaclass 就放弃”的原决定，单独做、单独评审。
- 动态绑定不在范围内：`globals()['C'] = …`、`setattr(mod, 'C', …)`、`setattr(C, 'm', …)`。另外，若基类不是本文件的类，而它的元类上有与方法同名的数据描述符，结果也会不同。
