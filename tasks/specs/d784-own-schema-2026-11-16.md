# 2026-11-16 索引里只认本工具自己建的可执行 schema 对象（D#784 / D#772 方案 C）

状态：已实现并提交（本地 main，未发版）。仓库公开：**0.191.1 没修掉的那条 vec0 崩溃的构造手法只在 `docs/d775-vec0-method.md`（gitignore），本文件和测试都不写它。**

## 背景

D#775（0.191.1）把 vendored sqlite-vec 升到 v0.1.9，修掉了 `vec_distance_*` / `vec_each` 两处内存错误，但仓库自带的 `.code-graph/index.db` 仍能让进程 abort：库里埋的对象（触发器、vec0 表，或改写的 `node_vectors`）能走到 sqlite-vec 的两处缺陷。GHSA-q67h-24gq-4263 的 Not fixed 一节公开了这一类。上游现状、位置和成因只写在本地的 `docs/d775-vec0-method.md` 与 `docs/d784-upstream-report-draft.md`（上游修复前不进被跟踪的文件）。

## 不覆盖（写进 CHANGELOG 的 Not covered）

- 我们自己的表里的伪造数据（含 `node_vectors` / `nodes_fts` 影子表）。health-check 的 `PRAGMA quick_check` 会对 vec0 调 xIntegrity，KNN 和删除会读影子表；没有已知崩溃路径。
- 改写我们普通表的建表 SQL（CHECK、DEFAULT、生成列、表达式索引）调用 sqlite-vec 的标量函数（注册为 INNOCUOUS）；v0.1.9 里这些函数没有已知缺陷。
- 敌意 schema 造成的挂起，以及埋的 DML 改写索引数据（D#772 已接受）。
- schema v10 之前（2026-07-18 前未再打开过）的索引若触发器原文不同会被拒绝，提示删除重建。

## 实施中的修正

- **旧 schema 版本**：第一版按"与本版本完全相同"比对，全量测试里 10 个失败：v1→v2 等迁移测试的 `nodes_fts` 列更少，v6 维度升级测试的 `node_vectors` 维度不同。两者都是代码支持的升级路径。改为：`nodes_fts` 只要求是 fts5 模块（SQLite 自带，参数怎样都不会跑 sqlite-vec 的代码）；`node_vectors` 除 `float[N]` 的维度外必须与本版本相同（不同维度由 `ensure_embedding_dim_consistency` 删表重建）。触发器的旧写法与现在相同（测试夹具和 9 个真实索引都是），不放宽。
- **用户点名的快照文件**（`open_readonly_named`）：读不到 schema 时原代码容忍（`user_version` 等探测都是 `unwrap_or`），第一版改成直接失败，5 个 snapshot inspect 测试因此失败。改为：读到外来对象才拒绝，读不到就放过；读不到 schema 的库上任何语句都跑不起来。
- **`type` 列**：第一版注释写"SQLite 不看 `type` 列"，这是错的。实测 SQLite 3.46.1：触发器、视图、虚表的 SQL 放在 `type` 不符的行里，加载时报 "malformed database schema"，什么都不执行。注释已改，相应用例已删。按 SQL 文本判断仍然成立：SQLite 写普通表和索引时会自己重建 `CREATE TABLE ` / `CREATE INDEX ` / `CREATE UNIQUE INDEX ` 前缀（`sqlite3EndTable` / `sqlite3CreateIndex`），以这些前缀开头的行只能解析成普通表或索引。
- **两个旧端到端测试**：`grep_says_so_when_it_could_not_annotate…` 的故障注入用 `ALTER TABLE nodes RENAME`，SQLite 会把我们的触发器改写到改名后的表上，于是撞上新检查——撞的是另一道守卫。改为改名前先删触发器，原断言不变。`test_cli_survives_vec_calls_planted_in_an_index_trigger`（D#775）原本靠埋的触发器执行来验证 sqlite-vec 0.1.9 的修复，现在触发器会被拒，改为断言三种触发器都被拒、且从未执行；`vec_distance_l2` 的修复改用仍然开放的途径钉住：改写表上的表达式索引（以 json_extract 的表达式错误作对照）。`vec_each` 是表值函数，放不进表达式索引，从提供的索引里已经没有途径能调到它。
- **重复检查**：`show` 一次会把 `reject_unowned_index` 跑两遍（CliContext 一遍，`open_impl` 又一遍），再加上真实连接上那次。`Database` 的构造函数改调只检查文件的 `reject_unowned_files`，schema 交给自己连接上的检查（失败即关闭）。

## CHANGELOG 草稿（发版时并入，最终文本见 CHANGELOG.md 0.195.0）

### fix: an index holding SQL code-graph does not write is refused

An index can carry SQL of its own, and SQLite runs it inside code-graph-mcp: a trigger on the tool's writes, a view or virtual table when it is read. With sqlite-vec loaded, a crafted `.code-graph/index.db` still aborted the process after 0.191.1 (GHSA-q67h-24gq-4263, Not fixed): on 0.194.0, `incremental-index` exits 134 on a vec0 assertion. Every open now reads the index's schema first and refuses it when a trigger, view or virtual table is not one this version creates (an older `nodes_fts` column set and another `node_vectors` dimension are still upgraded): `incremental-index` and every query exit 1 naming the objects, `health-check --json` reports `reason: refused`, and the MCP server exits before it answers. On the same crafted index this version exits 1 where 0.194.0 aborted, and leaves the file as it was. Nine indexes built by versions from INDEX_VERSION 71 to 140 opened unchanged. Each command pays for one more schema read: `show` 2.2 → 3.3 ms and `health-check --json` 74.8 → 78.4 ms (medians of 40 interleaved runs on this repository, both built from source). The sqlite-vec defects are reported upstream.

Not covered:
- SQL in the tool's own tables still runs: a CHECK, DEFAULT, generated column or index expression in a rewritten table runs on the tool's writes, and can call SQLite's functions and sqlite-vec's scalar functions (no known defect in v0.1.9).
- Forged rows in the tool's own tables, including the vector and full-text tables' internal ones, are read as data: `health-check`'s integrity check and vector search read them. No path to a crash is known.
- An index last opened before schema v10 (0.101.0, 2026-07-18) whose triggers differ from today's is refused; deleting `.code-graph/index.db*` rebuilds it.
