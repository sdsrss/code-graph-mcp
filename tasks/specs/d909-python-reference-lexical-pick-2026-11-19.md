# 2026-11-19 D#909：Python 引用在同文件的同名定义里只绑它的作用域看得见的那一个

## 为什么

用户授权：“继续完成剩余的工作”（2026-11-19，0.203.0 发版之后）。

先用 D#905 的作用域判定器（`tasks/d905-scope-oracle/reforacle.py`）量 0.203.0 全新索引里剩下的错边，按类别和默认是否可见分开（`oracle_by_type.py`、`reforacle.py`，五个语料）。默认可见的错边里最大的一类是 references 的 `nested-def->elsewhere`：引用看得见的是本函数（或外层函数）里嵌套的 `def`/`class`，边却同时绑到了同文件其他函数里的同名嵌套定义。全部是 `extracted`，默认所有查询都显示。

| 语料 | 这一类 | Python references 总数 |
|------|------|------|
| 标准库 | 214 | 3,601 |
| nltk | 28 | 1,170 |

| 本仓库 | 26 | 251 |
| daagu | 610 | 4,064 |

其余默认可见的类别都小一个量级：calls 的局部值绑到 `extracted`（标准库 117、daagu 59）、例外文件里的内建名调用（标准库 97 条可见）。

## 决定

- **沿用裸调用已有的规则（D#714 A3）。** 裸调用带 `call_at`（调用的起始字节），`visible_same_file_targets` 在同文件同名候选里只留这个位置看得见的最内层定义；看得见词法定义而又到不了类成员时，同文件的同名方法也去掉；一个都看不见时全部保留。引用目前 `call_at: None`，所以全部保留。
- **改法：** 两条 Python 引用路径（值位置 `extract_python_value_reference`、注解 `extract_python_type_reference`）给裸名带上位置；注解里 `a.b` 的 `b`（属性尾）不是裸名，不带。是否到得了类成员沿用 `mark_python_class_body_calls`（它对所有带位置的关系都判定）。
- **只删不加：** 规则只从同文件候选里拿掉，一个都看不见时原样保留，看得见时至少留下最内层那个，所以输出 ⊆ 0.203.0，同文件不会变成跨文件。
- **增量与重建：** 只看这个文件自己的文本和节点，按构造一致；不需要新的扇出。
- **已知近似（与裸调用相同）：** 词法范围是整个 `def` 节点，含参数和返回注解；Python 在外层求值它们。所以函数头里的名字会看见这个函数自己的嵌套定义。先不细化，用判定器 A/B 看语料里有没有因此丢掉的对边。

## 实现中的修正

- **Python 的 `class` 原来没有词法范围。** 第一版只给引用带上位置，注解那行（嵌套 `class Row`）仍然两边都绑：`lexical_scope` 只在提取 `def` 时计算。Python 的 `class` 和 `def` 一样把名字绑在所在的作用域，所以 `treesitter.rs` 的类分支对 Python 也算词法范围（同一分支 JS、Dart 也走，只限 Python）。这也改变了裸调用：嵌套类的 `Row()` 现在同样按作用域挑（判定器里 calls 的 `nested-class->elsewhere`：daagu 56、标准库 2、flask 2）。D#714 的调用表加了两行；把 `language == "python"` 改成不成立的变异，3 行类形状都失败。
- **函数头里的注解（提交 744c66e9 之后，发版前补上）。** 写 CHANGELOG 的 Not covered 前先复现了“已知近似”：`class Row` 在模块级，`def a(x: Row) -> Row:` 里又嵌套 `class Row`。0.203.0 绑两条（对的 `Row@1`、错的 `Row@6`）；744c66e9 只剩错的 `Row@6`，丢了对边。五个语料里没有这种写法，但这是本次改动新造成的丢对边，所以修掉，不写进 Not covered。
  - 改法：`py_annotation_at`。名字落在某个 `def` 的函数头里（从 `def` 开始到函数体开始：名字、参数、返回注解）时，位置取那个 `def` 前一个字节（`def` 在第 0 字节时取 `usize::MAX`，没有函数的范围包含它）；其余注解仍取名字自己的位置。函数头区间由 `scope_scan` 的那一次遍历顺手记下（`ScopeScan::headers`，`PY_DEF_HEADERS`）；函数头里写不了 `def`，区间互不相交，按起点二分查找。
  - 第一版是从名字沿 `type`/`generic_type`/`type_parameter` 往上爬到 `def`（`Node::parent` 每次从根往下找）。交替计时（各 3 次均值，0.203.0 → 爬树版）：480 KB、泛型嵌套 150 层的注解 1.05 → 3.77 s；c14（988 KB，函数嵌套 100 层，每个 20 个带注解的参数）8.27 → 13.51 s。不带函数头处理的 744c66e9 构建是 1.18 s、8.2–8.6 s，所以开销全在爬树。改成二分查找后见验证记录。值位置不需要：参数默认值里的名字被旧排除整个拿掉了（实测 `def f(cb=handler, *, k=[handler])`、`def g(cb=lambda: handler)`，`f`、`g` 各嵌套 `def handler`，模块也有 `def handler`：0.203.0 和改后都不发任何边），装饰器本来就在 `def` 外面。
  - 测试加了四行（参数与返回注解、嵌套函数的参数读外层函数的类、泛型参数和带默认值的参数、文件第 0 字节的 `def`），改前前两行失败（`a@5 -> Row@6`、`inner@4 -> Row@5`）。爬树版的五个变异都被抓到（不往泛型上爬、漏掉带默认值的参数、位置取在 `def` 上、第 0 字节取 0、不认返回注解）；二分查找版的四个变异也都被抓到：位置取在 `def` 上、第 0 字节取 0、不记录函数头（写成条件永不成立，能编译）、不看区间右端（嵌套类那行也失败）。
  - 裸调用在函数头里（`def f(x=make())`，`f` 嵌套 `def make`）有同样的近似，D#714 起就有，这次不动。
- **测试表里两行期望写错了，按 base 的实际结果改正：** 被装饰函数的节点从装饰器那一行算起（`g@4`）；类体里的引用来源是 `<module>` 节点。
- **`abdiff.py` 的比较键加了起始行。** 同文件同名的嵌套定义路径、名字、类型都相同，原来的键不分行号，base 独有的计数被算到 base 里同键的第一行上，判定器去判的往往是 head 也保留的对边（第一次 A/B 判为“正确”的 262 条，references 244、calls 18，其中 261 条是这样，剩下 1 条见下）。加了行号后重跑，见下。
