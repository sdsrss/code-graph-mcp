# pre-edit 影响摘要：用 Stop 检查的按语言读法确定"改了哪个定义"

## 背景

pre-edit 钩子（`claude-plugin/scripts/pre-edit-guide.js`）在 Edit 改了函数签名时注入调用方摘要。它选"被编辑的定义"的办法是：8 条正则按数组顺序，第一条命中的就是；再用 `headerAt` 看这段签名文字在 new_string 里还在不在（在，就当只改了函数体，静默退出）。代码注释写明：这条规则换过三次，每次都在评审里出回归，所以保留到"有按语言的设计、并且每种语言都有语料"为止。

Stop 检查（`stop-impact.js`）已经有一套按语言的读法：`LANGS` 列出 29 种扩展名的定义形式和签名结束位置，`readHeader` 按括号深度找签名结尾，`allSignatures` / `signatureChanged` 已经过多轮评审。

## 证据（2026-10-23，本机会话记录）

- 语料：`~/.claude/projects` 下 1,057 份会话记录（固定深度 glob）里的全部 Edit/MultiEdit 片段，去重后 4,066 个，其中 2,607 个的扩展名在 `LANGS` 里。脚本在 `tasks/pre-edit-pick/`；语料本身含用户代码，只留在 scratchpad，不入库。
- 现行规则会去查影响面的片段 95 个。其中 27 个选中的名字在旧片段里根本不是定义：Rust 的 `if !x.is_empty() {`、`match parse_with_deadline(..) {` 被"JS 方法 / Go 函数"那条正则当成定义；JS 注释里的 "the function already …" 被当成 `function already`；字符串字面量里的 `def main():`。
- 现行规则真正送达的摘要：会话记录里有 122 条 `[code-graph:impact]`，其中 96 条来自旧版钩子（现行规则在同一片段上不会选同一个名字），不计。其余 26 条里，23 条确实改了签名；3 条（12%）选的是 Rust 调用点（`parse_with_deadline`、`normalize_rel_path`、`may_write_index`），注入的是"这个函数改了签名"的假摘要。
- 漏报：同一语料里，现行规则判为"只改函数体"、但读法看到有定义的签名变了的片段有 24 个：16 个是 `headerAt` 在参数里的 `{`（解构参数、默认值 `{}`）处截断了签名；8 个是片段里第一个定义没改、后面的定义改了。
- 签名修改样本（审计的 `sig_edits.py`，26 次"改了签名、其他文件有调用方"的编辑）：现行规则注入 8 次；0.178.0 的 D#560 补上 worktree 里的 8 次；剩下的漏报里，第一个定义被选中而改的是后面那个 4 次，解构参数截断 2 次。

## 方案

只改 pre-edit-guide.js 选定义的那一步，对 `LANGS` 能读的文件生效：

1. 现行规则照旧选出 `symbol`，并照旧 `logEdit(symbol)`。
2. 读法对旧、新片段各跑一次 `allSignatures`。两边都有读数时：
   - 读法认为 `symbol` 的签名变了 → 用 `symbol`（现行规则若因 `headerAt` 截断判为只改函数体，这里改为继续）。
   - 否则，取旧片段里按出现顺序第一个签名变了的定义（`signatureChanged` 不带 symbol，任何签名变化都算，和现行"签名文字变了就算"的口径一致），并对它补一次 `logEdit`，让 Stop 检查也看到它。
   - 一个都没有 → 静默退出。
3. 读法没有读数（扩展名不在 `LANGS`、签名超过 600 字符、超长行）→ 完全按现行规则。

不做：TS 的 `export const f: T = (…) =>` 等读法也不认识的形式（D#372(4)），改选定义之外的任何逻辑（冷却、`--file`、同文件多定义的定位），可选参数追加是否算变化（沿用现行口径：算）。

## 预期效果（同一语料上模拟，`tasks/pre-edit-pick/sim_new.js`）

4,066 个片段中：75 个摘要不变；26 个不再出摘要（全部是非定义：调用点、注释、字符串）；1 个从注释里的 `already` 换成真正改了签名的 `dbUnusableRemedy`；新增 26 个（逐条人工核对后写入验证记录）。其余 3,938 个照旧不出摘要。

## 验收标准

- AC1：每种形态一个测试，修改前失败、修改后通过：Rust 调用点 `match f(x) {` 不出摘要；JS 注释 "function already" 后面的真实定义改了签名 → 出该定义的摘要；解构参数 `function f(a, { b })` → `{ b, c }` 出摘要；片段里第二个定义改了签名 → 出第二个的摘要，并记入 Stop 检查。
- AC2：现行规则已经正确出摘要的形态不变：现有 `pre-edit-guide.test.js` 全部通过；语料差分里"现行规则出摘要、读法确认签名变了"的片段，新规则选的名字与现行完全相同（脚本断言，0 例外）。
- AC3：读法没有读数的文件完全按现行规则：一个 `.sh` / 超长签名的测试。
- AC4：耗时：钩子在 8 KB 片段上的额外耗时有实测数字，写进验证记录；预算内（钩子总预算 4 s）。
- AC5：语料差分（新增 / 删除 / 换名三类）逐条列出，新增的每一条人工核对签名确实变了。
- AC6：全量 JS 测试通过；发版前由新的子代理评审。
