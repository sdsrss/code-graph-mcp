# D#229 — "0 个调用者"要说明可信度，并给出下一步

## 目标

`refs` / `find_references`（以及 `callgraph` / `impact` 的空调用者结果）回答"没有调用者"时，必须同时说明这个"0"有多可信，并给出一个能直接执行的核对办法。真没有调用者的情况，回答不能变得更啰嗦、更费轮次。

## 缺陷（实测）

tokio 1.41.1，`tokio/src` 下的非测试函数，用 rust-analyzer 的标准答案（`scripts/scip_oracle/run.sh --dump-gold`，7,908 个调用对）对照：

| 类型 | code-graph 在任何置信度都答 0 | 其中 rust-analyzer 找到 ≥1 个调用者 |
|---|---|---|
| 方法 | 1,291 | 228（17.7%） |
| 自由函数 | 83 | 14（16.9%） |

也就是说，对方法说"0 个引用"，大约每 6 次错 1 次。现在的输出把这个"0"说成已经确认：

- CLI：`No references found for 'remove'.` 加上 `(no dynamic-dispatch site names 'remove')`
- MCP：`total_references: 0`，`boundaries: {sites: [], total: 0}`

tokio 试点里，`LinkedList::remove` 在库代码里有 12 个调用者，code-graph 一条边都没有。Haiku 得到"0"以后，把 50 轮全部用完，得分 0.0。

`boundaries` 模块只披露动态派发（反射、事件名、字符串键、函数引用），并在文档里明确排除了直接调用 `save(…)`，理由是"静态边，或解析器缺口，不属于派发"。解析器缺口目前没有任何地方披露。

## 候选方案

**A. 统计源码里的调用写法（推荐，先离线测）**
结果为空时，在项目的非测试代码里统计调用这个名字的写法（Rust 的 `.name(`、`::name(`、`.name::<T>(`），去掉注释、字符串和定义本身。
- N > 0：说明有 N 处、分布在 M 个文件里的调用写法，没有一处解析到这个定义（图分辨不出它们调用的是哪个同名定义），并给出 grep 命令。
- N = 0：说明"没有任何调用写法"，这比现在的"0"更可信。

离线模拟（正则统计，只去掉注释，测试代码没有排干净，所以是上限估计），针对 1,291 个答 0 的方法：

| | 有调用写法 | 没有调用写法 |
|---|---|---|
| rust-analyzer 有调用者 | 209 | 19 |
| rust-analyzer 没有调用者 | 844 | 219 |

- 触发 1,053 次（81.6%）。触发时真有调用者的占 209/1,053 = 19.8%，即约 4/5 是误报。
- 真有调用者的 228 个里能覆盖 209 个（91.7%）。
- 不触发的 238 个里，真有调用者的只有 19 个（8.0%）。

误报主要来自常见名字（`poll`、`drop`、`fmt`、`new`），以及通过 trait 派发调用的实现。一个可以提高命中率的改进：只统计所在函数还没有一条 `calls` 边指向任何同名定义的调用写法。这样已经解析到别的同名定义的写法会被去掉。要先离线测，再决定是否值得加。

**B. 固定提示，不做统计**
方法答 0 时加一句"接收者类型推不出来的方法调用不会产生边，空列表不能证明没人调用"。这和 MCP 的 `instructions` 里已有的话重复，提供不了新信息。不推荐。

**C. 提高召回（D#150 接收者类型推断）**
这是根因修复，但成本高，以前的尝试引入过错误边。它和 A 不冲突：A 披露的是 C 修完后剩下的缺口。

## 接受的写法（先写语料，再写实现）

只统计调用写法：后面紧跟 `(` 或 turbofish。字段读取（`a.b`）、`use` 导入、`fn name` 定义、注释、字符串、测试文件和测试节点里的写法都不统计。每种语言的调用语法单独列表，复用 `graph::boundaries` 去掉注释和字符串的扫描，再按 `boundaries/tests.rs` 的样子写表驱动语料测试。第一版只覆盖 Rust、Python、JS/TS 三种语言；其它语言不统计，并在输出里写明"未扫描"，和 `boundaries` 的 `not scanned` 规则一致。

## 级别与发布要求

这会改变每个用户默认看到的输出，而且输出是给模型读的，所以按 L3 处理：
- 进入实现前需要你批准；
- 版本号升 minor（0.166.0）；
- CHANGELOG 顶部写迁移说明；
- 回退方式：固定旧版本号；
- 在 release notes 里写明这个变化。

## 测量计划

1. **离线（免费）**：先实现统计逻辑，在 tokio 上用标准答案重算上面两张表，并加上"所在函数没有同名边"的改进。如果命中率低于 15%，或者覆盖率低于 80%，就停下来重新设计。
2. **付费 A/B（Haiku，上限 $5，需要你批准）**：
   - 前提：先修 D#232 F8，评分器目前允许一行裸名同时满足同文件里两个同名评分项。
   - 用例：`linked-list-remove`、`registration-poll-read-ready`、`spawn-blocking`，再加 2 个"真没有调用者但有调用写法"的对照用例，用来测误报要多花多少轮次。
   - 两组：基线二进制和带披露的二进制，每组每个用例跑 3 次，共 30 个会话。按上次试点 Haiku 每会话约 $0.175 估算，大约 $5.3，所以对照用例只跑 2 次，把总数压到 $5 以内。
   - 指标：召回、轮次、费用。
   - 样本量只够看出大的差别（比如召回从约 0.3 升到 0.8），属于试点，不是定论。

## 不在范围内

- callgraph/impact 的同名合并：已记为 D#237，基线是默认置信度下 4,433 个调用对藏掉 29 个。
- 提高方法调用的召回（D#150）。
